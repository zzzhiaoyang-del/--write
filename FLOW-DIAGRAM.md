## 🔍 关键检查点

### 检查点 1: 用户登录状态
```
位置: 所有 API 调用之前
检查: supabase.auth.getUser()
失败: 返回 401 "未登录"
```

### 检查点 2: Supabase Storage
```
位置: /api/digital-human/upload
检查: digital-human-videos 存储桶是否存在且为 Public
失败: 返回 500 "视频上传失败"
```

### 检查点 3: D-ID API Key
```
位置: /api/digital-human/clone
检查: process.env.DID_API_KEY 是否有效
失败: 返回 500 "D-ID API调用失败"
```

### 检查点 4: 数据库写入
```
位置: /api/digital-human/clone
检查: digital_humans 表是否存在且有正确权限
失败: 返回 500 "保存失败"
```

## 🐛 常见错误流程

### 错误 1: 上传失败
```
用户上传视频
    ↓
POST /api/digital-human/upload
    ↓
❌ Storage 存储桶不存在
    ↓
返回 500 错误
    ↓
前端显示 "视频上传失败"
```

**解决**: 创建 `digital-human-videos` 存储桶并设为 Public

### 错误 2: 未登录
```
用户点击提交
    ↓
POST /api/digital-human/upload
    ↓
❌ 用户未登录
    ↓
返回 401 错误
    ↓
前端显示 "未登录"
```

**解决**: 先登录应用

### 错误 3: D-ID API 失败
```
视频上传成功
    ↓
POST /api/digital-human/clone
    ↓
❌ D-ID API Key 无效或积分不足
    ↓
返回 500 错误
    ↓
前端显示 "数字人创建失败"
```

**解决**: 检查 D-ID API Key 和积分

## 📱 前端状态管理

```
初始状态: loading = false, progress = ''
    ↓
用户点击提交
    ↓
loading = true, progress = '正在上传视频...'
    ↓
上传成功
    ↓
progress = '视频上传成功，正在创建数字人...'
    ↓
创建成功
    ↓
progress = '数字人创建成功！'
    ↓
2 秒后跳转到列表页
    ↓
loading = false
```

## 🔄 状态轮询机制

```
列表页面加载
    ↓
获取所有数字人
    ↓
筛选出状态为 "processing" 的数字人
    ↓
如果有处理中的数字人
    ↓
启动定时器（每 5 秒）
    ↓
对每个处理中的数字人调用 check-status API
    ↓
如果状态变为 "completed" 或 "failed"
    ↓
刷新整个列表
    ↓
继续轮询直到没有处理中的数字人
```
